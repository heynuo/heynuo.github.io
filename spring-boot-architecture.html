Spring Boot Enterprise Architecture: Clean REST APIs & DTOs

👤 HeyNuo 📅 September 28, 2026 ☕ Java & Spring Boot ⏱ 8 min read

Writing a quick @RestController that returns a database entity is fine for a weekend prototype. But in enterprise systems handling millions of financial requests or concurrent users, that approach breaks down fast: entities leak database columns to the public web, business rules scatter across HTTP endpoints, and unhandled exceptions return raw stack traces.

This guide walks through the architectural patterns used across production Spring Boot 3 applications: strict 3-tier layering, isolated Request/Response DTOs, declarative validation, and centralized exception management.

💡 Core Principle: A controller should only speak HTTP (status codes, headers, parameter extraction). A service should only speak domain logic (business invariants, calculations). A repository should only speak data access.

1. The 3-Tier Layered Architecture

Every maintainable Spring Boot application adheres to strict unidirectional dependency flow:

🌐 1. Web Layer (`@RestController`)

Accepts HTTP requests, validates incoming JSON DTOs with @Valid, and returns standardized ResponseEntity<T> payloads.

⚙️ 2. Business Layer (`@Service`)

Coordinates transactions (@Transactional), enforces business constraints, and orchestrates domain entity operations.

🗄️ 3. Persistence Layer (`@Repository`)

Interfaces extending JpaRepository that translate entity queries into optimized SQL. Never expose entities outside this boundary!

2. Decoupling with DTOs & Bean Validation

Never return or accept JPA Entities (e.g. UserEntity) directly in controllers. Doing so causes:

  • Over-posting attacks: Malicious clients can update internal fields like isAdmin or accountBalance.
  • Infinite JSON recursion: Bidirectional JPA relationships (@OneToMany) trigger StackOverflowError during Jackson serialization.
  • Tight coupling: Database schema migrations instantly break client applications.

3. Production Code: Order Management API

Below is a clean implementation demonstrating input validation, mapping, and response encapsulation:

☕ OrderController.java & OrderService.java 
// 1. Immutable Request DTO with Jakarta Validation
public record CreateOrderRequest(
    @NotBlank(message = "Customer ID is required")
    String customerId,

    @NotNull(message = "Order total cannot be null")
    @DecimalMin(value = "0.01", message = "Order total must be at least $0.01")
    BigDecimal totalAmount,

    @NotEmpty(message = "Order must contain at least one item SKU")
    List itemSkus
) {}

// 2. Controller Layer
@RestController
@RequestMapping("/api/v1/orders")
public class OrderController {
    private final OrderService orderService;

    public OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    @PostMapping
    public ResponseEntity placeOrder(@Valid @RequestBody CreateOrderRequest request) {
        OrderResponse response = orderService.processOrder(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(response);
    }
}

// 3. Service Layer with Business Rules
@Service
public class OrderService {
    @Transactional
    public OrderResponse processOrder(CreateOrderRequest req) {
        // Business Invariant Check
        if (req.totalAmount().compareTo(new BigDecimal("10000.00")) > 0) {
            throw new HighValueOrderReviewException("Orders over $10,000 require fraud review");
        }
        String orderId = "ORD-" + UUID.randomUUID().toString().substring(0, 8).toUpperCase();
        return new OrderResponse(orderId, req.customerId(), "CONFIRMED", req.totalAmount());
    }
}

4. Centralized Exception Handling (`@RestControllerAdvice`)

Instead of wrapping every controller method in messy try/catch blocks, enterprise Spring Boot applications use an intercepting advice layer:

☕ GlobalExceptionHandler.java 
@RestControllerAdvice
public class GlobalExceptionHandler {

    // Catch Bean Validation errors (@Valid)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity> handleValidationErrors(MethodArgumentNotValidException ex) {
        Map fieldErrors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(err -> 
            fieldErrors.put(err.getField(), err.getDefaultMessage())
        );

        Map body = Map.of(
            "timestamp", Instant.now(),
            "status", HttpStatus.BAD_REQUEST.value(),
            "error", "Validation Failed",
            "fieldErrors", fieldErrors
        );
        return ResponseEntity.badRequest().body(body);
    }

    // Catch Domain Exceptions
    @ExceptionHandler(HighValueOrderReviewException.class)
    public ResponseEntity> handleHighValue(HighValueOrderReviewException ex) {
        return ResponseEntity.status(HttpStatus.UNPROCESSABLE_ENTITY).body(Map.of(
            "timestamp", Instant.now(),
            "status", 422,
            "message", ex.getMessage()
        ));
    }
}
⚡ Intercepted Error Response
POST /api/v1/orders with empty customerId & negative amount: HTTP/1.1 400 Bad Request { "timestamp": "2026-09-28T15:20:00Z", "status": 400, "error": "Validation Failed", "fieldErrors": { "customerId": "Customer ID is required", "totalAmount": "Order total must be at least $0.01" } } [Security & Observability]: Internal stack trace suppressed; client receives actionable JSON error.

5. Hands-On Challenge: Idempotent Payment Processor

🎯 Challenge Prompt: Design a payment processing endpoint that prevents duplicate charge requests when a network glitch causes the mobile app to retry. Requirements:
  • Extract an Idempotency-Key HTTP header using @RequestHeader.
  • Verify if the key has been processed in a distributed cache (e.g. Redis). If yes, return the previous response with 200 OK immediately without re-charging.
  • If novel, execute the charge and record the key.
☕ IdempotentPaymentService.java (Challenge Solution) 
@Service
public class PaymentProcessingService {
    private final ConcurrentMap idempotencyStore = new ConcurrentHashMap<>();

    public PaymentReceipt processPayment(String idempotencyKey, PaymentRequest req) {
        // Fast path: Idempotent replay protection
        if (idempotencyStore.containsKey(idempotencyKey)) {
            System.out.println("⚠️ Duplicate request detected for key: " + idempotencyKey);
            return idempotencyStore.get(idempotencyKey);
        }

        // Execute payment gateway transaction
        PaymentReceipt receipt = new PaymentReceipt(
            "TX-" + UUID.randomUUID().toString().substring(0, 8),
            req.amount(),
            "SUCCESS",
            Instant.now()
        );

        idempotencyStore.put(idempotencyKey, receipt);
        return receipt;
    }
}

// Verification:
PaymentProcessingService service = new PaymentProcessingService();
PaymentRequest req = new PaymentRequest(new BigDecimal("75.00"), "CARD-9012");
String key = "req-uuid-9901-alpha";

PaymentReceipt first = service.processPayment(key, req);
PaymentReceipt second = service.processPayment(key, req); // Replay attack or retry

System.out.println("First call TX ID:  " + first.transactionId());
System.out.println("Second call TX ID: " + second.transactionId());
System.out.println("Instances identical: " + (first == second));
