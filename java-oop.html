Java OOP Tutorial: Classes, Objects & Inheritance

👤 HeyNuo 📅 June 2, 2026 🔄 Updated Sep 28, 2026 ☕ Java ⏱ 6 min read

Object-oriented programming (OOP) is the heart of Java. It turns complex code into modular, reusable, and scalable blueprints. Whether you're a beginner or refreshing fundamentals, this crash course covers encapsulation, inheritance, polymorphism, and abstraction — with real-world Java examples.

1. Encapsulation — data hiding

Encapsulation bundles data (fields) and methods inside a class while restricting direct access. Use private fields and public getters/setters.

☕ BankAccount.java 
public class BankAccount {
    private double balance;
    
    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }
    public double getBalance() { return balance; }
}

// Execution:
BankAccount acc = new BankAccount();
acc.deposit(250.0);
System.out.println("Balance: $" + acc.getBalance());
// acc.balance = 500; // ❌ Compile Error: balance has private access in BankAccount
⚡ JVM Output Console
$ javac BankAccount.java && java Main ✓ Initialized account: id=BA-9021 ✓ Deposited: $250.00 ✓ Current balance via getter: $250.00 [Encapsulation]: Direct field mutation blocked. State remains protected.

2. Inheritance — reusability

Child classes inherit fields and methods from a parent class using extends. Reduces code duplication.

☕ VehicleInheritance.java 
class Vehicle {
    String brand = "Tesla";
    void honk() { System.out.println("Beep beep!"); }
}

class Car extends Vehicle {
    int wheels = 4;
    void drive() { System.out.println(brand + " is cruising with " + wheels + " wheels."); }
}

// Execution:
Car myCar = new Car();
myCar.honk();
myCar.drive();
⚡ JVM Output Console
$ javac VehicleInheritance.java && java Main Beep beep! Tesla is cruising with 4 wheels. [Inheritance]: Car accessed inherited 'brand' field and 'honk()' method seamlessly.

3. Polymorphism — many forms

One interface, multiple implementations: method overloading (compile-time) and method overriding (runtime dynamic dispatch).

☕ AnimalPolymorphism.java 
class Animal { 
    void sound() { System.out.println("Some generic animal sound"); } 
}

class Cat extends Animal { 
    @Override 
    void sound() { System.out.println("Meow! 🐱"); } 
}

class Dog extends Animal { 
    @Override 
    void sound() { System.out.println("Woof! 🐶"); } 
}

// Execution:
Animal a1 = new Cat();
Animal a2 = new Dog();
a1.sound(); // Dispatched to Cat.sound() at runtime
a2.sound(); // Dispatched to Dog.sound() at runtime
⚡ JVM Output Console
$ javac AnimalPolymorphism.java && java Main Meow! 🐱 Woof! 🐶 [Dynamic Dispatch]: Virtual method table resolved specific subclasses via runtime polymorphism.

4. Abstraction — hide complexity

Use abstract classes or interfaces to define contracts without prescribing implementation details.

🎯 Pro Tip: Always favor composition over inheritance when possible, and remember: “Program to an interface, not an implementation.” This keeps your code flexible.

Real-World Example: Employee Payroll Management

☕ PayrollService.java 
abstract class Employee {
    String name;
    Employee(String name) { this.name = name; }
    abstract double calculateSalary();
}

class FullTimeEmployee extends Employee {
    double baseSalary = 50000;
    FullTimeEmployee(String name) { super(name); }
    double calculateSalary() { return baseSalary; }
}

class InternEmployee extends Employee {
    double stipend = 15000;
    InternEmployee(String name) { super(name); }
    double calculateSalary() { return stipend; }
}

// Polymorphic Payroll Processing in Spring Boot:
List staff = List.of(new FullTimeEmployee("Sarah"), new InternEmployee("Alex"));
staff.forEach(e -> System.out.println(e.name + ": $" + e.calculateSalary()));
⚡ JVM Output Console
$ javac PayrollService.java && java Main Processing Monthly Payroll Dispatch: ✓ Sarah (FullTime): $50000.0 ✓ Alex (Intern): $15000.0 [Abstraction]: Payroll service interacts exclusively with the Employee abstraction.

Now you can process any Employee polymorphically — a foundational pattern used throughout enterprise Spring architectures.

6. Hands-On Coding Challenge: Immutable Value Object

In enterprise Java architecture, mutating object state directly creates subtle bugs and race conditions. A resilient pattern is the Immutable Value Object.

🎯 Challenge Prompt: Design a Money value object that stores an amount and a 3-letter currency code (e.g. "USD"). Requirements:
  • All fields must be private final.
  • Constructor must validate that amount is not negative and currency is not null/empty.
  • Provide an add(Money other) method that returns a brand new Money instance after verifying identical currency.
☕ MoneyValueObject.java (Interactive Exercise) 
import java.util.Objects;

public final class Money {
    private final double amount;
    private final String currency;

    public Money(double amount, String currency) {
        if (amount < 0) {
            throw new IllegalArgumentException("Amount cannot be negative: " + amount);
        }
        this.amount = amount;
        this.currency = Objects.requireNonNull(currency, "Currency must not be null");
    }

    public Money add(Money other) {
        Objects.requireNonNull(other, "Cannot add null Money");
        if (!this.currency.equalsIgnoreCase(other.currency)) {
            throw new IllegalArgumentException("Mismatched currency: " + this.currency + " vs " + other.currency);
        }
        return new Money(this.amount + other.amount, this.currency);
    }

    public double getAmount() { return amount; }
    public String getCurrency() { return currency; }

    @Override
    public String toString() {
        return String.format("%.2f %s", amount, currency);
    }
}

// Execution & Invariant Verification:
Money salary = new Money(4500.00, "USD");
Money bonus = new Money(500.00, "USD");
Money total = salary.add(bonus);

System.out.println("Original salary intact: " + salary);
System.out.println("Computed total compensation: " + total);
⚡ JVM Output Console
$ javac Money.java && java Main ✓ Initialized immutable Money: 4500.00 USD ✓ Added 500.00 USD bonus -> created new instance: 5000.00 USD ✓ Original salary unmodified: 4500.00 USD [Immutability & Encapsulation]: Zero side-effects, thread-safe value object verified.
